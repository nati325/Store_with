# חנות לעסקים (bulk-shop)

חנות אינטרנטית למכירת מתנות, מוצרי מותג וציוד לאירועים לחברות, בכמויות.
Next.js 14 (App Router) + Prisma + PostgreSQL. עברית RTL, שקלים, מע״מ 18%.

## מה יש
**זהות האתר**: השם ("שי בכמות") והלוגו (קופסת מתנה) הם זמניים. השם מוגדר ב-`SITE_NAME`, והלוגו ב-`src/components/Logo.tsx` ו-`src/app/icon.svg`. לפני שמחליטים על שם סופי יש לבדוק זמינות שם וסימן מסחרי.

**לקוחות**
- קטלוג עם חיפוש, מיון וסינון לפי קטגוריה
- עמוד מוצר: טבלת מחירי כמות שמדגישה את המדרגה הפעילה, כמות מינימום, וחישוב מיידי
- עגלה (נשמרת בדפדפן). המחירים מחושבים בשרת בלבד
- הזמנה ללא תשלום באתר: פרטי חברה, ח.פ., כתובת, מועד אירוע והערות
- דף מעקב להזמנה עם סטטוס, וכפתור "לתשלום" כשהוגדר קישור תשלום
- העלאת לוגו להדפסה בעגלה, ותצוגה מקדימה של הלוגו על המוצר בעמוד המוצר (בדפדפן בלבד)
- אישור הדמיה: העסק שולח הדמיה, והלקוח מאשר או מבקש שינויים בדף ההזמנה
- שיטות מיתוג וזמן אספקה בכל מוצר, ומשלוח למספר כתובות
- הצעת מחיר להדפסה או PDF מהעגלה, הזמנה חוזרת בלחיצה, ומילוי אוטומטי של פרטי חברה
- חיפוש לפי תקציב ליחידה, שאלות נפוצות, כפתור וואטסאפ ופרטי קשר
- דפי חג: קמפיינים עם מועד מומלץ להזמנה, שמוצגים בדף הבית
- "העובד בוחר": קישור פרטי לחברה עם תקציב, וכל עובד בוחר מתנה אחת
- בקשת הצעת מחיר או דוגמית לכמויות חריגות או התאמה אישית
- עמודי תקנון, פרטיות והצהרת נגישות (תבניות, ראו "לפני עלייה לאוויר")
- מצב כהה, מובייל, SEO (sitemap, robots, כותרות)

**ניהול (`/admin`, סיסמה ב-`ADMIN_PASSWORD`)**
- סקירה: הזמנות חדשות, הכנסות, שווי פתוח, בקשות הצעת מחיר
- הזמנות: חיפוש וסינון, עמוד פרטים, עדכון סטטוס, תשלום ב-Cardcom או קישור תשלום ידני, הערות פנימיות, אימייל ללקוח
- אישור הזמנה להדפסה או PDF (אינו חשבונית מס), וייצוא כל ההזמנות ל-CSV
- הצעות מחיר: רשימה וסימון כטופלה
- מוצרים: יצירה, עריכה, מדרגות מחיר, שיטות מיתוג, זמן אספקה, תגיות, העלאת תמונה, השבתה ומחיקה
- הזמנות: צפייה בלוגו של הלקוח, שליחת הדמיה, סטטוס "בייצור", ועדכון אוטומטי ללקוח באימייל
- דפי חג: יצירה והפעלה של קמפיינים. העובד בוחר: יצירת תוכניות, סיכום בחירות וייצוא CSV

**אבטחה**: דף ההזמנה מוגן בטוקן סודי בכתובת (מספר ההזמנה לבדו לא מספיק), מחיר מחושב בשרת, הגבלת קצב להזמנות/הצעות/כניסת מנהל, שדה פיתיון נגד בוטים, העלאות עם בדיקת סוג ותוכן, קישור תשלום רק https, הגנה מהזרקת נוסחאות ב-CSV.

## הרצה מקומית
```bash
cp .env.example .env
docker compose up -d          # Postgres
npm install
npm run db:push               # יצירת טבלאות
npm run db:seed               # מוצרי דוגמה
npm run dev
```
חנות: http://localhost:3000 · ניהול: http://localhost:3000/admin

## הגדרות (`.env`)
| משתנה | תיאור |
|---|---|
| `DATABASE_URL` | חיבור ל-Postgres |
| `ADMIN_PASSWORD` | סיסמת הניהול. חובה להחליף |
| `SITE_URL` | כתובת האתר, לקישורים באימיילים וב-SEO |
| `SMTP_URL`, `MAIL_FROM`, `ADMIN_EMAIL` | אימייל. בלי `SMTP_URL` ההודעות נרשמות ללוג בלבד |
| `UPLOAD_DIR` | תיקיית תמונות. חייבת להיות על אחסון קבוע |
| `SITE_NAME` | שם האתר (זמני: "שי בכמות") |
| `WHATSAPP_NUMBER`, `CONTACT_PHONE`, `CONTACT_EMAIL` | פרטי קשר. וואטסאפ בפורמט בינלאומי, למשל `972501234567`. כפתור וואטסאפ מופיע רק אם הוגדר |
| `PLAUSIBLE_DOMAIN` | סטטיסטיקות Plausible. אופציונלי |
| `CARDCOM_TERMINAL`, `CARDCOM_API_NAME`, `CARDCOM_DOC_TYPE` | סליקה וחשבוניות (ראו "סליקה וחשבוניות") |

## סליקה וחשבוניות (Cardcom)
החיבור נכתב לפי המפרט הרשמי של Cardcom API v11 (`LowProfile/Create` ו-`LowProfile/GetLpResult`).

**איך זה עובד**
1. הלקוח שולח הזמנה (בלי חיוב). אתם בודקים ומשנים את הסטטוס ל"אושרה".
2. בדף ההזמנה מופיע כפתור "לתשלום בכרטיס אשראי". הלחיצה פותחת דף תשלום מאובטח אצל Cardcom, ופרטי הכרטיס לא עוברים אצלנו.
3. אחרי התשלום, האתר מאמת מול Cardcom (לא סומך על ה-webhook לבד) שהתשלום הצליח, שייך להזמנה הזו, ובסכום המדויק (כולל מע״מ). רק אז ההזמנה מסומנת "שולמה".
4. Cardcom מפיק חשבונית מס קבלה אוטומטית ושולח אותה ללקוח. הקישור לחשבונית מופיע בדף ההזמנה ובניהול.

**הפעלה**
1. בקשו מ-Cardcom: מספר טרמינל ו-ApiName (שם משתמש API). ודאו שמודול ההפקת מסמכים פעיל בחשבון.
2. ב-`.env`: `CARDCOM_TERMINAL`, `CARDCOM_API_NAME`, ו-`SITE_URL` הציבורי של האתר (Cardcom קורא אליו ב-webhook).
3. `CARDCOM_DOC_TYPE`: `TaxInvoiceAndReceipt` (חשבונית מס קבלה) לעוסק מורשה או חברה, `Receipt` לעוסק פטור, או ריק כדי לא להפיק מסמך.
4. בלי `CARDCOM_TERMINAL` ו-`CARDCOM_API_NAME` הכפתור לא מופיע, ונשארת האפשרות הידנית: להדביק קישור תשלום (https) בכל הזמנה ולסמן "שולמה".

**לפני הפעלה בפועל, בצעו עסקת ניסיון בסכום קטן וודאו:**
- החשבונית מציגה נכון את הסכום והמע״מ. האתר שולח שורות כולל מע״מ שסכומן שווה בדיוק לסכום החיוב. אם החשבונית מוסיפה מע״מ מעל הסכום, יש לעדכן את `grossLines` ב-`src/lib/cardcom.ts`.
- ההזמנה עברה ל"שולמה" אחרי התשלום.
- הכפתור "בדיקת תשלום מול Cardcom" בניהול מאמת תשלום ידנית אם ה-webhook לא הגיע.

**מה נבדק ומה לא**: הקוד נבדק מקצה לקצה מול שרת Cardcom מדומה שנכתב לפי המפרט (תשלום מוצלח, ביטול, סכום שגוי, webhook מזויף, כפילות), ובטסטי יחידה. הוא לא נבדק מול Cardcom עצמו, כי אין טרמינל בדיקה. עסקת הניסיון למעלה היא הבדיקה הזו.

## פריסה
`Dockerfile` מצורף: מבנה, מסנכרן סכמה בעלייה ומרים את האתר. צריך Postgres, ואחסון קבוע ל-`UPLOAD_DIR`. הגבלת הקצב נשמרת בזיכרון, ולכן מתאימה למופע שרת אחד.
ה-Dockerfile לא נבדק בסביבת הפיתוח (לא היה Docker זמין).

## לפני עלייה לאוויר
- להחליף `ADMIN_PASSWORD`, ולהגדיר `SITE_URL` ו-SMTP
- להשלים ולבדוק משפטית את `/terms`, `/privacy`, `/accessibility` (מסומנות כתבניות עם שדות [להשלמה])
- להפיק חשבוניות מס במערכת הנהלת חשבונות. האתר מפיק רק אישור הזמנה

## גיבוי ו-CI
- `scripts/backup.sh` מגבה את המסד ואת התמונות ושומר 14 גיבויים אחרונים (דורש `pg_dump`)
- `.github/workflows/ci.yml` מריץ בדיקת טיפוסים, טסטים ובנייה בכל דחיפה ל-main וב-Pull Request
